## Required corrections

### P1-01 — A paired player can be changed back to preliminary registration

**Source:** [`backend/src/AutoKorsak.Domain/TournamentEditor.cs`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/backend/src/AutoKorsak.Domain/TournamentEditor.cs#L110-L173), `Apply(..., isNew: false)`.

**Observed:** `AddPairing` / `ApplyPairing` refuses a new pairing for a preliminary participant, but `UpdateParticipant` allows setting `Preliminary = true` on a player who already appears in one or more pairings. The update then persists a state that cannot be created using the pairing editor.

**Expected:** A newly requested transition from final to preliminary registration must not leave an existing pairing attached to an ineligible player. For P0, reject that transition with a localized domain conflict and an actionable message. Do not automatically erase historical games or invalidate a pre-existing imported state solely because unrelated fields were edited.

**Tests:** Final participant + a pairing (with and without a recorded result) → attempt to set preliminary → rejected; unchanged participant and pairing after reload. Existing preliminary player without games can still be edited/finalized.

### P1-02 — Converting a played pairing to a bye can retain its game result

**Source:** [`backend/src/AutoKorsak.Domain/TournamentEditor.cs`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/backend/src/AutoKorsak.Domain/TournamentEditor.cs#L206-L270), `UpdatePairing` / `ApplyPairing`; [`frontend/src/pages/PairingEditor.tsx`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/frontend/src/pages/PairingEditor.tsx#L143-L166).

**Observed:** When an existing `BlackWins` or `WhiteWins` pairing is switched to `IsBye=true`, the result control becomes disabled but keeps its original value in the form. The backend bye validation allows this if the incoming result matches the previous result. The pairing becomes a bye while still carrying a two-player game's result; standings ignore the bye, but XML export retains its result.

**Expected:** Converting a regular game to a bye must clear its game result, with the existing explicit discard confirmation when necessary. It must not silently reinterpret a completed game or leave a contradictory bye/result combination. Keep imported historical byes and their unknown legacy semantics untouched unless explicitly edited.

**Tests:** Played regular pairing → bye conversion without confirmation fails; confirmed conversion stores `Unset` and exports/reimports coherently. Unplayed regular pairing → bye produces `Unset`; editing an imported bye without conversion does not unexpectedly erase retained legacy data.

### P2-01 — Normal empty rounds are falsely reported as skipped-round scoring problems

**Source:** [`backend/src/AutoKorsak.Domain/Standings.cs`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/backend/src/AutoKorsak.Domain/Standings.cs#L71-L85).

**Observed:** For every unpaired, non-preliminary participant in any counted round, the calculator raises `skippedRoundsNotAdjusted`, even when the round has no pairings/results and is simply awaiting manual pairing. That warning claims unsupported skipped-round scoring before any actual skipped-round event is known.

**Expected:** Separate explicitly absent players (`NotPlayingRounds`) and genuinely incomplete/unplayed rounds from confirmed scoring irregularities. Do not report an unsupported skipped-round scoring adjustment merely because the current round is still empty. Add a regression test for a fresh tournament with players and no pairings.

### P2-02 — Unsaved settings can be lost on in-app navigation

**Source:** [`frontend/src/pages/SettingsPage.tsx`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/frontend/src/pages/SettingsPage.tsx#L89-L101).

**Observed:** The dirty-form guard covers browser `beforeunload`, but navigating to Standings/Pairings/Players with React Router unmounts the form without a confirmation. Unsaved settings are discarded.

**Expected:** Warn and let the referee stay or discard before navigating away from a dirty settings form, including SPA navigation. Ensure normal saved navigation remains uninterrupted. Add a focused browser/component check.

### P2-03 — The Players list omits three agreed columns

**Source:** [`frontend/src/pages/PlayersPage.tsx`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/frontend/src/pages/PlayersPage.tsx#L67-L111); approved P0 scope `§5.4` and agreed players-list workflow.

**Observed:** The list displays club but not country, team, or coach, despite those data existing in the model/editor.

**Expected:** Display the missing attributes, or provide an accessible visible-column control if table width warrants it. Keep Ukrainian/English column labels and the existing desktop-first approach. No redesign of the general standings layout is requested.

### P2-04 — Invalid/out-of-range legacy round absence values are silently discarded

**Source:** [`backend/src/AutoKorsak.LegacyXml/LegacyXmlImporter.cs`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/backend/src/AutoKorsak.LegacyXml/LegacyXmlImporter.cs#L143-L171); [`LegacyXmlExporter.cs`](https://github.com/unnameddimka/autokorsak-online/blob/0cc161681004bcee68018205bb542a61dfdc9a95/backend/src/AutoKorsak.LegacyXml/LegacyXmlExporter.cs#L116-L130).

**Observed:** Invalid `NotPlayingInRound` values are converted to 0 and filtered out (along with out-of-range values) during import. On export, the reconstructed list can replace the original elements, causing silent loss.

**Expected:** For a *known, supported* element, reject malformed/out-of-range data with a localized validation error, **or** explicitly retain the unmappable source value for lossless round-trip with a clear limitation. Do not silently discard it. Add malformed and out-of-range XML regression cases.
